# ticket-collection-web 計画書

チケット半券コレクションの Web 版（ホーム画面に置ける PWA）。
仕様の元は `docs/handoff.md`（iOS 版 `d18c1e7` 時点）。この計画書は「何を・どの順で・どう確かめるか」を決める。

- 作成日：2026-10-12

---

## 決めたこと

### ユーザーに確認して決めたこと（2026-10-12）

| 項目 | 決定 |
|---|---|
| 写真からの自動読み取り（OCR） | **後回し**。まず AI の貼り付け＋手入力で完成させる。最後のフェーズで Tesseract.js を実物の半券で試し、入れるか決める |
| 作りの形 | **ビルドなし・複数ファイル**（`index.html`＋ES モジュール＋`sw.js`＋`manifest.webmanifest`） |
| 置き場所 | **GitHub Pages ＋ PUBLIC リポジトリ** |
| iOS 版のデータ | **移す**。iOS 版に書き出し機能を足し、Web 版のバックアップ形式で出す |

### こちらで決めたこと（変えたいときは言ってください）

| 項目 | 決定 | 理由 |
|---|---|---|
| バックアップの形式 | **画像込みの JSON 1ファイル**（画像は Base64） | 依存ライブラリなし。iOS 版は `JSONEncoder` が `Data` を自動で Base64 にするので、書き出し機能が小さく済む。ZIP より約3割大きいが、数百枚なら問題ない |
| 画面の作り | **Preact ＋ htm をリポジトリに同梱**（CDN から読まない） | ビルドなしで部品単位の再描画ができる。素の JS で全体を作り直すと入力中のフォームが壊れる（過去の教訓）。オフラインで動くよう同梱する |
| 保存先 | **IndexedDB**（半券・出演者・画像 Blob を別ストア）。起動時に `navigator.storage.persist()` を要求 | 画像を Base64 で持たず Blob のまま保存し、一覧はサムネイルだけ読む |
| 画面遷移 | ハッシュ（`#/ticket/<id>` など） | GitHub Pages で追加設定なしに動き、戻るボタン・スワイプで戻るが効く |
| テスト | `node --test`（Node 標準）で、画面に依存しない処理をテスト | ビルドなしのまま回せる |
| iOS 版の今後 | Web 版へ移行し終えるまで並行。移行後は使わない想定 | 移行の手順にだけ影響する |

### 守ること（`docs/handoff.md` 2章・CLAUDE.md より）

- 従量課金の API・クラウド OCR をアプリから呼ばない
- 半券の画像・データをアプリから外部に送らない（ユーザーが共有メニューで送るときだけ）
- 実物の半券画像・氏名・番号をリポジトリに入れない。テストデータは架空値
- 各フェーズの完了は **iPhone の Safari（ホーム画面に追加した状態）の実機** で確かめる

## ファイル構成（予定）

```
index.html               画面の器。CSS もここ
manifest.webmanifest     アプリ名・アイコン・standalone 表示
sw.js                    Service Worker（全ファイルをキャッシュしてオフラインで動かす）
icons/                   ホーム画面のアイコン
vendor/                  preact・htm（同梱）
src/
  app.js                 起動・ハッシュ遷移
  model/                 ← 画面に依存しない。Node でテストする
    ticket.js            項目・カテゴリー・下書き（draft）
    text.js              正規化（全角半角・大文字小文字）、価格の解釈
    performers.js        出演者の照合・統合・孤立した出演者の削除
    grouping.js          並び替え・グループ・検索
    ai-format.js         AI の指示文と答えの読み取り
    backup.js            書き出し／読み込みの形式と検証
  store/db.js            IndexedDB
  image.js               画像の縮小（長辺2000px／600px の JPEG）
  views/                 画面（一覧・詳細・編集・めくる・出演者・設定）
tests/                   node --test
docs/                    引き継ぎ資料・テストデータ
```

## バックアップ形式（案）

```json
{
  "format": "ticket-collection-backup",
  "version": 1,
  "exportedAt": "2026-10-12T10:00:00+09:00",
  "performers": [
    { "id": "uuid", "name": "", "reading": "", "aliases": [] }
  ],
  "tickets": [
    {
      "id": "uuid",
      "title": "", "subtitle": "", "category": "",
      "performerIds": ["uuid"],
      "performanceDate": "2026-10-10",
      "openTime": "17:00", "startTime": "18:00",
      "venue": "",
      "seat": { "floor": "", "block": "", "row": "", "number": "", "gate": "", "note": "" },
      "price": 8800, "issuer": "",
      "ocrText": "", "comment": "",
      "createdAt": "ISO 8601", "updatedAt": "ISO 8601",
      "image": "Base64 の JPEG（なければ null）"
    }
  ]
}
```

項目名は iOS 版（`Ticket.swift`）に合わせ、席だけ `seat` にまとめる。サムネイルは入れず、読み込み時に作る。

## 危ないところと対策

| 危ないところ | 対策 |
|---|---|
| Safari がデータを消す | ホーム画面に追加して使う前提を画面で案内。`persist()` を要求。書き出しを促す |
| standalone で共有・ダウンロードが効かない | Phase 0 で実機確認。駄目なら代わりの手順（画像を長押し保存してから AI アプリで選ぶ等）を決める |
| 大きい画像で固まる | 取り込み時に一度だけ縮小。描画中に展開しない。めくる画面は近くの数枚だけ読む |
| ChatGPT の答えで固まる（iOS 版で未解決） | 貼り付けた答えはただのテキスト。項目を表示して確認してから反映 |
| Service Worker の古いキャッシュが残る | 版番号つきキャッシュ。更新の通知と再読み込みを用意 |
