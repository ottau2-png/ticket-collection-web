# 引き継ぎ資料：チケット半券コレクション Web版

iOS ネイティブ版（`../../ticket-collection/`）と同じ目的のアプリを、Web アプリ（ホーム画面に置ける PWA）として作り直すための資料。
新しい会話では、この資料をもとに計画書（`tasks/todo.md`）を作る。

- 作成日：2026-10-12
- 元のプロジェクト：`../ticket-collection`（SwiftUI、iOS 18 以上。Phase 4 ＋追加機能まで完成）
- 元のプロジェクトのコミット：`d18c1e7`（この資料の内容はこの時点の iOS 版に基づく）

---

## 1. なぜ Web 版か

iOS 版の不満点を解消するため。

- 無料の開発者アカウントで入れているので、**7日ごとに Mac につないで入れ直す必要がある**
- iPhone 以外（PC・Android）で見られない

Web 版の得失（iOS 版と比べて）。

| 項目 | Web版 | 補足 |
|---|---|---|
| 一覧・ギャラリー・検索・並び替え・カテゴリー・出演者の管理 | 同等 | |
| 大きく表示して左右にめくる・ピンチ拡大 | ほぼ同等 | 横向きは画面全体に効く（その画面だけ横にする制御はできない） |
| 撮影 | ○ | 撮影・写真選択はできるが、iOS の書類スキャナのような傾き補正・自動の切り抜きはない |
| 写真からの文字読み取り | △〜✗ | iOS の Vision は使えない。端末内なら Tesseract.js（日本語）で、精度は明らかに低く遅い。クラウド OCR は従量課金なので使わない |
| AIで読み取る（答えの貼り付け） | 同等 | 主な入力手段にする候補 |
| データ保存 | △ | ブラウザ内（IndexedDB）。ホーム画面に追加しないと Safari が消すことがある。機種変更でも消えるので、書き出し／読み込みが必須 |
| 同期 | ✗ | サーバーを持たないなら手動の書き出し／読み込みのみ |
| 配布 | ◎ | 入れ直し不要。URL を開いてホーム画面に追加するだけ |

ユーザーの運用：写真からの自動読み取りより、**Claude アプリで読み取った答えを貼り付ける**方法を主に使っている（ChatGPT では不具合あり、6章）。

---

## 2. 変えない決まり（ユーザーの方針）

- **従量課金の API は使わない**（Claude API・クラウド OCR などをアプリから呼ばない）。AI はユーザー自身の AI アプリ（月額プラン）で使い、答えを貼り付けて取り込む
- 半券の画像には氏名・座席・チケット番号が写るので、**アプリから外部に送らない**。送るのは、ユーザーが共有メニューで自分の AI アプリを選んだときだけ
- 個人を特定できる情報をリポジトリに入れない（テスト用データは架空の値に置き換える。実物の半券画像はコミットしない）
- 返答・文書は日本語
- 動作確認は、**iPhone の Safari（ホーム画面に追加した状態）**の実機で行う。シミュレータやPCブラウザで満足しない

## 3. 機能の仕様（iOS 版で実現したもの）

### 3.1 半券の項目

| 項目 | 内容 | 備考 |
|---|---|---|
| 公演名 | 必須 | |
| カテゴリー | 下の選択肢から1つ、または未設定 | 文字列で保存（選択肢を増やしても壊れないように） |
| ツアー名・サブタイトル | | |
| 出演者 | 複数。別エンティティで多対多 | 入力は「、」「,」「，」改行区切りのテキスト |
| 公演日 | 日付 | |
| 開場・開演 | それぞれ任意（オン／オフ）。時刻のみ | オンにしたときの初期値は 17:00 ／ 18:00 |
| 会場 | | |
| 席 | 階・ブロック・列・番号・ゲート/扉・その他（自由入力） | 整理番号は「その他」に「整理番号 A779」 |
| 価格 | 整数（円）。任意 | 入力は「8,800円」「¥12,000」「８８００」も受け付ける |
| 発券元 | 自由入力（ぴあ・e+・ローチケなど） | |
| 画像 | 元画像（長辺2000px JPEG）＋サムネイル（長辺600px） | |
| 読み取った文字 | OCR の全文 | |
| コメント | 複数行 | |
| 作成日・更新日 | | |

カテゴリーの選択肢（この順）：ライブ／演劇／ミュージカル／クラシック／お笑い／スポーツ／展示会／映画／その他

出演者：名前・よみ（並び替え用）・別名（表記ゆれ）。照合は大文字小文字・全角半角を無視する。

### 3.2 画面と操作

- **一覧**
  - 表示の切替（選択は保持）：公演日の新しい順／古い順／年ごと／出演者ごと／カテゴリーごと
    - 年ごと・出演者ごと・カテゴリーごとは見出しに件数。出演者が複数の半券は各出演者の下に出す。出演者なしは「出演者なし」、カテゴリーなしは「未設定」で最後
    - 出演者の並びは、よみがあればよみ順、なければ名前順
  - リスト／ギャラリーの切替（選択は保持）
    - リストの行：サムネイル、公演名、出演者、「カテゴリー 日付 会場」を1行（長ければ末尾省略）。スワイプで削除
    - ギャラリー：2列のタイル。半券の全体が見えるよう枠に収める（切り抜かない）。画像なしはカテゴリーのアイコン。下に公演名と日付。長押しで削除
  - 検索：公演名・ツアー名・カテゴリー・会場・出演者名（別名含む）・コメント。大文字小文字・全角半角を無視
- **登録・編集**
  - 各欄の左に見出しを常に表示（値が入ってもどの欄か分かるように）
  - 文字の入った欄に灰色の × を出し、押すとその欄だけ空にする
  - キャンセルで何も変えない（フォームは下書きを編集し、保存時だけ反映）
  - 保存・削除はその場で確実に書き込む
- **詳細**：画像（タップで全画面・ピンチ拡大）、全項目、コメント、編集、削除（確認つき）
- **めくって見る画面**：ギャラリーのタイルから全画面で開き、左右にめくる。並びはギャラリーと同じで、画像のある半券だけ（重複なし）。ピンチ・ダブルタップで拡大、拡大中はめくらずに画像を動かす。タップで文字やボタンを隠す。上に「×・3 / 12・詳細」、下に公演名・ツアー名・日付・会場。横向き対応
- **出演者の管理**：一覧（枚数・別名）→ 編集（名前・よみ・別名、その出演者の半券一覧）。表記ゆれの統合（半券を付け替え、元の名前・別名を統合先の別名に残して削除）。どの半券にも紐づかない出演者は自動で削除
- **撮影・写真から登録**：画像を選ぶと自動で読み取り、空欄だけを埋める。「〜を自動入力しました」と表示。読み取った文字を1行ずつ表示し、行をタップ →「公演名に入れる／ツアー名／出演者に追加／会場／席（その他）／発券元／コピー」
- **AIで読み取る**：①指示文をコピー ②画像を共有メニューで AI アプリへ送る ③AIの答えを貼り付けて取り込む。AIの答えは入力済みの欄も上書きする（空の項目は触らない）

### 3.3 写真から自動入力する項目

**公演名・ツアー名・出演者（登録済みの名前・別名と一致したものだけ）・会場・価格の5項目だけ**。
公演日・開場／開演・席・発券元・カテゴリーは誤読が多いので、写真からは取り出さない（ユーザーの判断）。

## 4. 読み取りの規則（iOS 版 `TicketParser` の要点）

Web 版で写真読み取りを作る場合の参考。OCR の各行は「文字＋位置（正規化座標・原点左下）」の形で受け取る想定。

- **正規化**：全角英数字・記号を半角に（カタカナは全角のまま）、全角スペース→半角、「￥」→「¥」
- **同じ高さの枠を1行にまとめる**：高さの6割以上が重なり、背の高さが2倍以内で、横に重ならないものだけ（行全体の範囲と比べると隣の行まで連鎖する。横に重なるのは上下に詰まった別の行）
- **価格**：「¥」付き（「¥4, 700」のような空白も許す）か「〜円」。「ドリンク」を含む行は除外し、残りの最大額
- **会場**：①「会場：〇〇」 ②ホール・アリーナ・ドーム・劇場・シアター・会館・スタジアム・武道館・センター・座・hall・arena・dome・theater・theatre・stadium・zepp で終わる行 ③どちらもなければ、日付の行のすぐ上の行（e+ でよくある並び）。席種の「アリーナ」だけの行・席・時刻・価格・日付・定型文の行は除く
- **公演名**：定型文の行（下記）・席・時刻・価格・日付・会場の行と、複数行にまたがった誤認識の枠（ほかの2行以上と縦に半分以上重なる）を除いた候補のうち、**日付・会場より上の行**の中で文字が最も大きいもの。前後の ★☆◆◇■□●○◎※* を除く
  - 定型文のキーワード：http, www., .com, .jp, 主催, 協力, 企画, 制作, 後援, お問, 問合, 問い合, TEL, 電話, 会場, 入場, 禁止, 不可, 発券, 注意, 整理番号, 税込, 指定, 様, familymart, ファミリーマート, セブン, 7-eleven, ローソン, ミニストップ, 開場, 開演, OPEN, START, ぴあ, イープラス, eplus, ローチケ, 楽天チケット, チケプラ。ほかに「チケット[ぴびひでぱ]あ」、「主催：〜」のような4文字以内の見出し＋コロンの行（見出し自体は誤読されやすい）、数字が半分を超える行
- **ツアー名**：公演名の直下の候補行で、tour・live・concert・ツアー・ライブ・公演・コンサートを含むもの
- **出演者**：登録済みの出演者の名前・別名が文中にあれば候補に
- **日付の判定**（行の見分けと AI の答えの読み取り用）：「2026年10月10日」「令和8年1月15日」「2026/10/10」「2026.10.10」「2005 9 29」。1950〜2100年、1〜12月、1〜31日
- **時刻**（AI の答え用）：「18:00」「18時30分」「6:30 PM」「午後6時30分」を24時間に

### 4.1 文字間隔の広い半券（チケットぴあの古い券など）

iOS の Vision は、文字間隔の広い横書きを**縦書きと誤認**して崩れる（縦に細長い枠が大量に出る）。
対策：2文字以上の枠のうち縦長（高さ×画像高 > 幅×画像幅×1.5）が3割以上なら、**画像を横に 0.6／0.55／0.5／0.45／0.4 倍へ縮めて読み直し**、項目ごとに多数決（同数なら最も多く項目が取れた結果）。公演名は単語ごとに、読み取られた綴りとその部分文字列の中から**編集距離の合計が最小の綴り**を採用（MOLL／SMOLLY／MOLLYS→MOLLY）。
Tesseract.js で同じ現象が起きるかは未確認。

### 4.2 テストデータ

`fixtures/ocr-fixtures.json`：実物の半券3枚（e+ 指定席、e+ スタンディング、ぴあ立見の各倍率）と架空の書式2つの OCR 結果と期待値。氏名・番号は架空の値に置き換え済み。Web 版のパーサーのテストにそのまま使える。
（注意：これは Vision の読み取り結果。Tesseract.js は行の分け方も誤読の傾向も違うので、Web 版では実物で取り直す必要がある）

## 5. AI で読み取る（指示文と答えの形式）

指示文（そのままコピーさせる）：

```
この写真はコンサートや舞台のチケット半券です。半券に書かれている内容を読み取り、下の形式だけで出力してください。
・項目名は変えずに、1行に1項目
・分からない項目は「:」の後ろを空欄にする
・公演日は YYYY-MM-DD、開場・開演は24時間表記の HH:MM
・価格は数字だけ（ドリンク代などの別料金は含めない）
・カテゴリーは次から1つ選ぶ：ライブ、演劇、ミュージカル、クラシック、お笑い、スポーツ、展示会、映画、その他
・出演者が複数なら「、」で区切る
・整理番号は「席その他」に「整理番号 A123」のように書く
・氏名、電話番号、チケット番号、URL は出力しない
・前置きや説明は書かない

公演名:
カテゴリー:
ツアー名:
出演者:
公演日:
開場:
開演:
会場:
階:
ブロック:
列:
番号:
ゲート・扉:
席その他:
価格:
発券元:
```

答えの読み取り：
- 前置きの文章・コードブロック（```）・箇条書き（- * • ・）・太字（**）・全角コロンを許容
- 上の項目名の行だけを拾う。値が空・「不明」「なし」「-」「ー」は無視。項目名の行が1つもなければ「読み取れませんでした」
- カテゴリーは選択肢にそろえる（「舞台」→演劇、「コンサート」→ライブ、合わなければ「その他」）。推測の手がかり語は下のとおり（上から順に調べる）
  - ミュージカル：ミュージカル, musical
  - クラシック：交響楽団, オーケストラ, フィルハーモニー, 管弦楽, リサイタル, 演奏会, クラシック, orchestra, symphony
  - お笑い：寄席, 落語, 漫才, お笑い, コント
  - スポーツ：" vs ", " vs.", 試合, 選手権, スポーツ
  - 展示会：展覧会, 展示, 美術展, 博覧会, 美術館, 博物館, エキシビション, exhibition、「〇〇展」で終わる語
  - 演劇：劇団, 演劇, 舞台, 芝居, 歌舞伎, 文楽, 狂言
  - 映画：映画, 上映, シネマ, cinema
  - ライブ：live, tour, ライブ, コンサート, concert, ツアー, フェス, ワンマン
- 価格は数字だけを取り出す

## 6. iOS 版で分かった注意点（Web 版にも関係するもの）

- **OCR は撮るたびに結果が変わる**（行の分かれ方・誤読）。1回の結果に合わせ込まず、実物の読み取り結果を架空値に置き換えた再現テストを先に書いてから直す
- 実物で外れた例：下部の大きな発券店名（FamilyMart）を公演名と誤認、「主催」→「主進」の誤読、日付が2行に分かれる、「18:00」→「1800」、ドリンク代を価格と誤認、「チケットぴあ」→「びあ」「であ」
- **ChatGPT の答えを取り込むと、iOS 26 実機で画面が反応しなくなる不具合が未解決**。Claude の答えでは起きない。ChatGPT 側で添付の上限にかかり、画像を読めないまま返した答えの中身が引き金と推測。Web 版では、取り込みの前に答えをテキスト欄で見せ、読み取れた項目数を表示してから反映する設計にすると安全
- iOS の `PasteButton`（システム管理の貼り付けボタン）は iOS 26 実機で問題が出た。Web 版でも、クリップボードを直接読む（`navigator.clipboard.readText`）より、テキスト欄に貼り付けさせる方が確実（Safari では許可の確認も出る）
- 共有メニューで画像を渡すときは、保存済みの JPEG をそのまま渡す（大きい画像の再描画・変換で固まった）。Web では `navigator.share({ files: [File] })`
- 画像の展開を描画のたびに行わない（重い）
- 公演名は1行に収まらない長さのことが多い（例：NOEL GALLAGHER'S HIGH FLYING BIRDS）。入力欄・一覧・タイルで省略や折り返しを考える

## 7. 計画の前に決めること（ユーザーに確認する）

1. **写真からの自動読み取りを入れるか**
   - 入れない（AI の貼り付けと手入力のみ）：最も簡単。ユーザーは主に Claude の貼り付けを使っている
   - Tesseract.js で入れる：日本語データ十数MB、精度・速度は iOS 版より落ちる。まず実物の半券で精度を試してから決めるのが安全
2. **作りの形**：単一 HTML（`keikyu-quiz` などと同じ。ビルド不要）か、ビルドありの構成か
3. **置き場所**：GitHub Pages など（データは端末内だけなので、ページ自体は公開でも個人情報は出ない）。リポジトリは PUBLIC／PRIVATE どちらか
4. **iOS 版から引き継ぐデータ**：既存の半券を移すか（移すなら iOS 版に書き出し機能を足す必要がある）
5. **バックアップの形式**：画像込みの1ファイル（JSON＋画像の Base64、または ZIP）を書き出し／読み込み
6. **iOS 版の今後**：並行して使う／Web 版に切り替えたら使わない
